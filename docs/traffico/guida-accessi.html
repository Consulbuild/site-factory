I dati veri partono da qui

Senza Search Console non sappiamo per quali ricerche Cavaliere compare, da dove arrivano i clic e se le modifiche funzionano. È il primo passo perché tutto il resto si misura contro questa base.

  1. Consenso di Cavaliere Build

    Fatto il 15/09/2026. Cavaliere accetta che il sito cavalierebuild.it venga modificato per portare più contatti. Ogni pubblicazione resta comunque approvata da te.

  2. Search Console: verifica cavalierebuild.it (facoltativo, per avere i dati subito)

    La verifica si può automatizzare e il software la farà da solo per ogni cliente (piano T2a): con le chiavi di Google Cloud e il token Cloudflare solo DNS scrive il record TXT, verifica il dominio, invia la sitemap e aggiunge info@consulbuild.com come proprietario. Farla a mano una volta per Cavaliere costa 5 minuti e ci dà i dati prima che T2a sia pronto.

    Con info@consulbuild.com su search.google.com/search-console:
    • «Aggiungi proprietà» → tipo Dominio → cavalierebuild.it.
    • Copia il record TXT e aggiungilo nel DNS del dominio su Cloudflare (tipo TXT, nome @).
    • Torna su Search Console e premi «Verifica» (se non passa subito, riprova dopo qualche minuto).

    Sblocca: la fotografia di partenza (ricerche, pagine, clic dall'Italia) e ogni misura dei risultati.

  3. Bing Webmaster Tools e la sua chiave

    Su bing.com/webmasters accedi con lo stesso account Google:
    • «Importa da Google Search Console»: i siti verificati arrivano già verificati.
    • Ingranaggio in alto → Accesso API → «Chiave API» → Genera.

    Chiave: Bing Webmaster (API key) · Sblocca: l'invio delle pagine nuove a Bing a ogni pubblicazione.

Google Cloud per il servizio Sito

Un progetto solo, nell'organizzazione consulbuild.com, per leggere Search Console dal software, verificare i domini nuovi da solo e misurare la velocità.

  1. Progetto e API abilitate

    Su console.cloud.google.com crea il progetto (es. site-factory-traffico), poi in «API e servizi → Libreria» abilita:
    • Google Search Console API
    • Site Verification API
    • PageSpeed Insights API
    • Chrome UX Report API

  2. Service account di scrittura (per il Mac)

    «IAM e amministrazione → Account di servizio → Crea» (es. sf-scrittura), poi «Chiavi → Aggiungi chiave → JSON»: si scarica un file.
    • Incolla il contenuto del file JSON nel campo dell'editor, poi cancella il file scaricato.
    • Non serve aggiungerlo a mano in Search Console: diventa proprietario da solo verificando il dominio col suo record TXT.

    Chiave: Google Cloud (service account di scrittura) · Sblocca: verifica dei domini nuovi e invio della sitemap a ogni pubblicazione.

  3. Service account di lettura (per il VPS)

    Stesso procedimento (es. sf-lettura), chiave JSON.
    • In Search Console lo aggiunge il software insieme a te durante la verifica (piano T2a).
    • Il JSON va nelle credenziali di n8n sul VPS, non nell'editor: te lo chiedo quando parte la raccolta notturna (piano T2b).

    Sblocca: la raccolta dei dati anche col Mac spento.

  4. Chiave API per la velocità

    «API e servizi → Credenziali → Crea credenziali → Chiave API», poi «Limita chiave» → solo PageSpeed Insights API e Chrome UX Report API.

    Chiave: Google Cloud (PageSpeed e CrUX) · Sblocca: punteggio e velocità misurata sui visitatori veri.

Se Google non ti lascia creare la chiave JSON («la creazione di chiavi per gli account di servizio è disattivata»), è una regola di sicurezza delle organizzazioni nuove: da amministratore la togli per questo progetto in «IAM e amministrazione → Criteri dell'organizzazione».

Prima della prima pubblicazione con le pagine nuove

Cloudflare e DataForSEO

  1. Secondo token Cloudflare, solo DNS

    Su Cloudflare: «Profilo → Token API → Crea token → Modello personalizzato». Permessi Zona: Lettura e DNS: Modifica, sulle zone dei domini dei clienti. Il token del deploy resta com'è.

    Chiave: Cloudflare (token solo DNS) · Sblocca: la verifica automatica in Search Console di ogni dominio cliente nuovo.

  2. DataForSEO

    Registrati su dataforseo.com con l'account dell'agenzia:
    • Ricarica 50 $: è credito prepagato, quindi è anche il tetto di spesa.
    • Nel pannello, sezione API: copia login e password API (la password API è diversa da quella del sito).

    Chiavi: DataForSEO (login e password) · Sblocca: le ricerche che la gente fa davvero nelle zone del cliente, chi compare oggi su Google e nelle mappe, la scheda Google consigliata.

Quando un cliente attiva il servizio Scheda

Scheda Google del cliente

  1. Accesso da Gestore

    Il cliente, dalla sua scheda su Google: «Impostazioni del profilo → Persone e accesso → Aggiungi» con info@consulbuild.com, ruolo Gestore. Tu accetti l'invito. La scheda consigliata la inserisci tu a mano.

    Non serve nessuna chiave per preparare la scheda consigliata: usa DataForSEO.

  2. Domanda di accesso alle API della scheda (più avanti)

    Serve solo per il monitor automatico delle schede (piano G3). Google la accetta da un account che gestisce una scheda verificata e attiva da almeno 60 giorni, con sito collegato; la risposta arriva in giorni o settimane. Te la preparo io quando ci arriviamo.

Cosa non serve

  • Developer token di Google Ads: DataForSEO dà gli stessi volumi senza approvazione.
  • Abbonamenti a strumenti SEO come Ahrefs o Semrush.
  • Places API di Google: non restituisce l'area servita delle schede.
  • Una licenza Google Workspace in più: basta info@consulbuild.com.
